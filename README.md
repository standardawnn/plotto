# Plotto 통합 모바일 프로토타입

제공된 Figma Make 세 프로젝트의 React 화면과 모션을 보존하고 연결한 모바일 프로토타입입니다. 데스크톱 웹 공동세션은 이번 범위에 포함하지 않습니다.

## 실행

Node.js 22.12 이상(검증 환경: 24.18)에서 이 폴더를 열어 실행합니다.

```sh
npm install
npm run dev
```

브라우저에서 http://localhost:4178 을 엽니다. 포트가 사용 중이면 터미널에 표시된 주소를 이용합니다.

```sh
npm run typecheck
npm run build
npm run preview
```

`dist/`가 완성된 정적 웹사이트입니다. `index.html`, `mobile.html`, `assets/`, `fonts/`를 함께 호스팅해야 합니다. 파일을 더블클릭하는 `file://` 실행은 지원하지 않습니다. 정적 호스팅은 도메인 루트 기준입니다.

## 체험 순서

1. 홈의 **브리핑 보기** → 겹친 카드를 눌러 펼치기 → Before/Now 카드를 눌러 맥락 확인 → Now의 **열기** → **수정부분만** → **저장하기** → 공유 대상 선택 → **공유하기**.
2. 기존 뒤로가기 버튼으로 홈에 복귀 → 하단 **프로젝트** → **이어서 하기** → 메시지 입력 영역 → 보내기. 원본의 분석·캐릭터 모션이 끝나면 **공동세션 예약하기**.
3. 주제 추천 또는 직접 수정 → 시간 휠 선택 → 메시지 확인 → **메세지 보내기** → **공동세션 하러가기**.
4. 자료조사 PDF 열기와 보드 복귀, 마이크·카메라·스피커 상태 전환 → 보드의 상단 뒤로가기 화살표로 세션을 마치고 의견 정리.
5. **의견 남기기** → 첨부파일 → 입력 영역 → 보내기 → 저장 완료 후 **팀원에게 전달하기** → 개인별 의견 분석 → **의견 보내기**. 기존 완료 메시지를 2.4초 보여준 뒤 프로젝트로 복귀합니다.

프로젝트의 새 자료 카드와 기획안 수정·자료조사 항목에서도 자료 확인으로 이동할 수 있습니다. 프로젝트의 홈 아이콘으로 첫 화면에 돌아갑니다.

## 디바이스 표시

- 데스크톱: 9:19.5 화면의 얇은 폰 프레임, 브라우저 크기에 맞춘 비례 축소.
- 오른쪽 상단 **디바이스 / 전체 화면** 또는 F 키로 전환. 동일 iframe을 유지하므로 진행 상태와 모션이 초기화되지 않습니다.
- 폰: 프레임과 외부 버튼이 사라집니다. 안전 영역을 고려하며, 짧은 화면에서는 UI를 자르지 않고 전체를 축소해 좌우 여백이 생길 수 있습니다.
- 원본 402×874 화면과 9:19.5 표시 영역(402×871)은 약 3px 차이가 있습니다. 고정 캔버스는 원본 비율대로 맞춥니다.

## 구성 및 보존 원칙

작업중개입 프로젝트의 프로젝트 홈·채팅·예약·공동세션을 중심 흐름으로 사용했습니다. 브리핑 홈은 통합 진입 화면이고, 알낳기 프로젝트가 개인별 의견 분석과 결과를 담당합니다.

| 경로 | 역할 |
| --- | --- |
| `src/modules/briefing` | 홈, 카드 다이얼, Before/Now 상세, 문서 검토·저장·공유 |
| `src/modules/intervention` | 프로젝트, 채팅 단계, 제안 모션, 주제·시간 예약, 세션 보드·자료 |
| `src/modules/opinion` | 자료 확인, 첨부·의견·저장 단계, 공유 안내, 개인별 분석·전달 |
| `src/shell.tsx`, `src/shell.css` | 화면 밖 디바이스 프레임과 표시 모드 |
| `src/mobile.tsx` | 각 원본의 React 앱과 CSS를 같은 출처의 별도 문서에 로드 |
| `src/journey.ts` | 프로젝트 간 이동과 탭 단위 Mock 상태 |
| `src/useNodeActions.ts` | 기존 Figma 노드에 레이아웃 변경 없이 이동 연결 |
| `public/assets/{project}` | 원본 이미지·SVG를 프로젝트별로 분리 |
| `src/baseline` | 개발 환경에서만 접근하는 병합 전 UI 비교용 원본 |

전역 CSS, Tailwind 초기화, 같은 이름의 애니메이션이 서로 영향을 주지 않도록 단일 외부 프레임 안의 문서를 바꿉니다. 동시에 여러 프로젝트의 애니메이션을 실행하지 않습니다. 화면을 이미지로 대체하지 않았습니다. React·Tailwind·Vite·Motion 의존성과 폰트는 한 번 설치하고 공통으로 제공합니다.

원본 화면 컴포넌트·CSS·키프레임은 에셋 경로 외에는 그대로입니다. 변경은 진입 상태, 기존 요소의 이동 처리, 예약 메시지 시간 반영, 타이머 해제 및 완료 후 복귀에 한정됩니다. `SessionFeedbackScreen`은 원본에서도 사용되지 않은 참고 화면이라 새 단계로 끼워 넣지 않았습니다.

## 남아 있는 범위와 제한

- AI 응답, 예약·참여자·공유·통화는 원본의 Mock 시나리오입니다. 실제 메시지 전송, 음성/영상 통화, AI 서버 요청은 하지 않습니다.
- 원본의 채팅 작성·의견 첨부는 미리 정의된 화면을 순차 전환하는 방식입니다. 자유 입력·실제 파일 업로드 기능으로 바꾸지 않았습니다. 예약 주제 수정과 세션 제안 화면의 입력창은 원본처럼 입력 가능합니다.
- 소스에 대상 화면이 없는 마이페이지, 일부 알림·다른 프로젝트, 회의록 확인·원문 보기·자료 추가 등의 장식 요소는 새 화면을 임의로 만들지 않았습니다. 핵심 체험 경로는 연결되어 있습니다.
- 새로고침은 해당 흐름의 진입 단계부터 다시 시작합니다. Mock 기록은 같은 탭의 세션 저장소에만 유지됩니다.
- Pretendard 파일 4개는 ZIP 원본에서 제공됩니다. 일부 원본 CSS에는 Figma의 Montserrat/SF Pro 및 Pretendard CDN 참조가 남아 있습니다. 외부 폰트 접근이 제한된 환경의 픽셀 동일성은 별도 확인이 필요합니다.
- 브라우저 크기 검사로 검증했으며, 실제 iOS/Android 기기에서 OS 키보드·노치 동작까지 확인한 것은 아닙니다.

## Figma Make에서 편집하기

원본 Design/Make 프로젝트를 덮어쓰거나 수정하지 않았습니다. 이 코드는 표준 React/Vite 프로젝트로 로컬 편집과 일반 정적 호스팅이 가능합니다.

Figma 공식 문서에서 확인되는 경로는 Make 코드 다운로드, 코드 편집기에서 파일 편집·붙여넣기, 파일/폴더 추가입니다. 새 Make 또는 복제본에 변경된 소스와 에셋을 추가하고 Make에 참조하도록 요청하는 수동 경로가 가능합니다. 다만 **외부 ZIP 전체를 가져와 이 다중 HTML·iframe 구성을 그대로 실행하는 자동 왕복 가져오기는 확인되지 않았습니다.** 이 프로젝트는 Make 안에서 재실행 검증하지 않았습니다.

Make → GitHub 내보내기는 지원되지만 외부 저장소 수정 사항이 Make로 자동 반영되지는 않습니다. 별도 Make 복제본에서 수동 반영한 뒤 `mobile.html` 진입점, Vite 설정, `/assets/` 경로가 유지되는지 확인해야 합니다. 지원 범위를 넘어 자동 변환하거나 원본을 덮어쓰지 마세요.
